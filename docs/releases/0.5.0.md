## Remaining release steps

1. Review and merge the integration after its SDK/container and Nextflow checks pass.
2. Create `v0.5.0` at the reviewed merged commit after code and CI review.
3. Dispatch **Prepare SDK release artifacts** for that tag. The workflow rejects
   a version mismatch, a different checkout, dirty source, or a tag not merged
   into `origin/main`. It records the exact source commit/tree and build epoch.
4. Require all four Linux amd64 CPU environments (`core`, `esm`, `dnabert2`,
   `sequence`) to build OCI and SIF artifacts, pass framework imports and pass
   native/Podman/Apptainer scoring parity. These probes do not establish model
   inference parity or performance on a particular HPC cluster.
5. Review each artifact's `release-source.json`, OCI inspection, tool versions,
   parity reports and `SHA256SUMS`. Consolidate the wheel/sdist only when their
   hashes agree across matrix jobs. Keep every environment's reports identified.
6. Dispatch **Publish reviewed SDK artifacts** with the successful preparation
   run ID and `dry_run=true`. It verifies all four checksum inventories and exact
   source identities, requires matching wheel/sdist bytes across jobs, and stages
   large assets using hard links on the GitHub runner. Inspect the small plan artifact.
7. Dispatch the same workflow with `dry_run=false` after review. It uploads a draft,
   verifies every server-side SHA-256 and size, then publishes. Interrupted drafts
   can resume only with identical assets. Existing public releases and mismatching
   draft assets are never overwritten. No local OCI/SIF download is needed.

No 0.5.0 release tag, release upload or public package publication occurred during
candidate validation. Release artifact preparation awaits reviewed merged source
and passing CI. The existing local wheel remains a candidate.

## Publication storage limits

[GitHub requires each release asset to be smaller than 2 GiB](https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases).
The publication validator rejects empty files and any asset at or above that limit.
There is no split-file workaround in this workflow. The v0.4.0 reference assets
are approximately 143–413 MB per OCI archive and 135–393 MB per SIF; these are
planning estimates, not the size of a future 0.5.0 build.

Publication requires at least 6 GiB free on a GitHub-hosted runner before artifact
download. The large files stay on that runner and upload directly to the release.
Only the small plan, checksums and validation receipt are retained as an additional
Actions artifact. This avoids consuming the local Mac's limited free disk.
