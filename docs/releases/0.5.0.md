## Remaining release steps

1. Review and merge the integration after its SDK/container and Nextflow checks pass.
2. Explicitly authorize creation of `v0.5.0` at the reviewed merged commit.
3. Dispatch **Prepare SDK release artifacts** for that tag. The workflow rejects
   a version mismatch, a different checkout, dirty source, or a tag not merged
   into `origin/main`. It records the exact source commit/tree and build epoch.
4. Require all four Linux amd64 CPU environments (`core`, `esm`, `dnabert2`,
   `sequence`) to build OCI and SIF artifacts, pass framework imports and pass
   native/Podman/Apptainer scoring parity. These probes do not establish model
   inference parity or performance on a particular HPC cluster.
5. Review each artifact's `release-source.json`, OCI inspection, tool versions,
   parity reports and `SHA256SUMS`. Consolidate the wheel/sdist only when their
   hashes agree across matrix jobs. Keep every environment's reports identified.
6. Publish the reviewed wheel, sdist, OCI archives, SIF files and verification
   receipts through a separately authorized GitHub release. The preparation
   workflow does not publish, upload submissions, create a tag or alter the database.

No 0.5.0 release tag, release upload or public package publication occurred during
candidate validation. Release artifact preparation remains blocked on reviewed
merged source and tag authorization, not on a claim that the existing local wheel
is already released.
